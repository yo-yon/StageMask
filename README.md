# StageMask

登壇・画面共有・録画のときに、**見せてはいけない画面の領域を隠す** Windows 向けのローカルアプリです。
画面の最前面に透明なウィンドウを重ねてマスクを描くので、プロジェクター、Teams/Zoom の画面全体の共有、OBS などの録画のすべてで隠れます。処理はすべて PC の中で行い、画面の内容を外部に送信しません。

> ⚠ **v0.5.16(試作版)**: Windows 実機でのビルドとテストは確認済みですが、動作確認は途中です。本番で使う前に、下の「[初回の動作確認チェックリスト](#初回の動作確認チェックリスト)」を必ず実施してください。

## できること

| 機能 | 内容 |
|---|---|
| 手動マスク | 画面上をドラッグして、隠す範囲を固定で配置する(移動・リサイズ・右クリックで削除) |
| ウィンドウ追従 | 指定したアプリ(例: Outlook)のウィンドウ全体を隠す。移動・リサイズに追従する |
| 自動検出(OCR) | 指定したアプリの画面を読み取り、メールアドレス・GUID・テナント名・APIキー・NGワードの部分だけを隠す |
| 画面全体モード | ルールがなくても、表示中のすべてのウィンドウを自動検出の対象にする(既定OFF) |
| 見た目 | 塗りつぶし / モザイク / ぼかし(手動マスク・ウィンドウ・自動検出のすべてで選択可) |
| マスク上の文字・画像 | 共通の文字・画像を設定し、マスクやルールごとに上書きできる。画像はマスク全体に敷き詰めて表示 |
| パニック | ホットキー1つで、全画面を黒く覆う |
| 操作パネルの非表示 | 操作パネル自体は画面共有・録画に映らない |
| マルチモニター | すべてのモニターに対応(拡張表示を想定) |

## 動作環境

- Windows 11(Windows 10 version 2004 以降でも動く想定)
- ビルド: .NET 10 SDK(Visual Studio 2026 の「.NET デスクトップ開発」ワークロード、または `dotnet` CLI)
- 自動検出を使う場合: Windows の **日本語の OCR 機能**(と、併用するなら英語の OCR 機能)が入っていること

### OCR 機能が入っているかの確認

PowerShell(管理者)で次を実行し、`Language.OCR~~~ja-JP~...` が `Installed` になっていれば利用できます。

```powershell
Get-WindowsCapability -Online | Where-Object { $_.Name -like 'Language.OCR*' }
```

入っていない場合は、「設定 → 時刻と言語 → 言語と地域」で日本語の言語パックを追加するか、上のコマンドで表示された名前を指定して `Add-WindowsCapability -Online -Name <名前>` で追加します。
起動後、操作パネル下部の状態欄に `OCR: ja, en` のように表示されれば利用できています。

## ビルドと起動

```powershell
git clone <このリポジトリ>
cd StageMask
dotnet test tests/StageMask.Core.Tests     # 検出ロジックのテスト
dotnet run --project src/StageMask.App     # 起動
```

### ダブルクリックで起動できる exe を作る

```powershell
powershell -ExecutionPolicy Bypass -File .\publish.ps1
```

テストを実行してから、`publish\StageMask.exe` を作ります。.NET ランタイムごと1つにまとめるため、.NET を入れていないPCでもこの exe だけで動きます。設定は `%APPDATA%\StageMask` に保存されるので、exe を別の場所に移しても設定は引き継がれます。

GitHub に push すると、`.github/workflows/build.yml` が Windows 上でテストと publish を実行し、exe を成果物として保存します。

## 使い方

1. 起動すると操作パネルが開きます(既定で、パネルは画面共有・録画に映りません)
2. **ウィンドウ** タブで、一覧からアプリを選んでルールを追加します
   - 「このアプリを常に隠す」… ウィンドウ全体を隠します(メール、チャット、管理画面など)
   - 「このアプリの機密情報を隠す(OCR)」… 画面は見せたまま、該当する文字だけを隠します(ブラウザーでのデモなど)
   - 「タイトルでも絞り込む」にチェックを入れると、タイトルが一致するウィンドウだけが対象になります
3. **自動検出** タブで、NGワード(顧客名・氏名など)を1行に1つずつ入力し、「適用・保存」を押します
4. 固定の場所を隠すときは、上部の **マスク編集** を ON にして、画面上をドラッグします
5. 本番中はホットキーで操作します

| ホットキー(既定) | 動作 |
|---|---|
| `Ctrl+Alt+M` | マスク全体の ON/OFF |
| `Ctrl+Alt+P` | パニック(全画面を黒く覆う)の ON/OFF |
| `Ctrl+Alt+E` | 手動マスクの編集モード |
| `Ctrl+Alt+D` | 自動検出の ON/OFF |
| `Ctrl+Alt+S` | 操作パネルを最前面に出す(マスクの下に隠れたとき) |

操作パネルは、操作している間(アクティブな間)だけマスクより前に表示されます。ほかのウィンドウに切り替えるとマスクの下に戻ります。マスク編集中もパネルのボタンは押せます。

操作パネルは WPF 標準の Fluent テーマ(Windows 11 風)で表示され、Windows のライト/ダーク設定に合わせて配色が変わります。「適用・保存」を押すと、ボタンの横に結果(✓ 反映・保存しました など)が表示されます。操作パネルのタイトルバーに、実行中のバージョン(例: `StageMask v0.3.1`)が表示されます。設定は `%APPDATA%\StageMask\settings.json` に保存されます(NGワードは暗号化)。エラーは同じフォルダーの `error.log` に記録されます。

## 自動検出の対象

| 分類 | 例 |
|---|---|
| メールアドレス | `yoh@contoso.com`、UPN。入力途中のもの(`yoh@`、`taro@exa` など、@ の前に英数字があるもの)も隠します(v0.5.7〜)。`@メンション` は対象外 |
| 識別子 | GUID(テナントID・環境IDなど)、`*.onmicrosoft.com`、`*.sharepoint.com`、`*.crm*.dynamics.com`、`*.blob.core.windows.net`、`*.vault.azure.net`、`*.openai.azure.com`、`*.azurewebsites.net` |
| 秘密情報 | `sk-...`、GitHub トークン、AWS アクセスキー、Google API キー、Slack トークン、JWT、Bearer トークン、PEM 秘密鍵、`AccountKey=` / `Password=` などの「キー=値」 |
| 汎用 | 大文字・小文字・数字が混在した長いランダム文字列(OFF にできます) |
| NGワード | 登録した語。全角/半角・大文字/小文字・空白の違いは無視。4文字以上は1文字の誤読まで許容 |

検出ロジック(`src/StageMask.Core`)は Windows に依存しないため、`dotnet test` で単体テストできます。

## セキュリティ設計

| 項目 | 対応 |
|---|---|
| 外部への送信 | ネットワーク通信を行うコードはありません。画面の取り込み・OCRはすべてPC内で処理します |
| 画面画像 | メモリ上でのみ扱い、ファイルには保存しません |
| NGワードの保存 | Windows のデータ保護 API(DPAPI)で暗号化して保存します。同じPC・同じWindowsユーザーでなければ復号できません。暗号化できない場合は保存しません |
| NGワードの表示 | 操作パネルでは普段は伏せ字にし、「表示して編集」を押したときだけ表示します。パネルから離れると自動で隠します |
| ウィンドウ一覧 | タイトルに件名やアドレスが含まれることがあるため、「一覧を更新」を押したときだけ表示し、パネルから離れると消します |
| フェイルクローズ | 自動検出の対象ウィンドウを検査できていない間(起動直後、取り込み失敗、真っ黒な画像、OCRエラー、処理の停止)は、ウィンドウ全体を隠します |
| 検出処理の暴走防止 | 正規表現の照合に時間の上限(200ミリ秒)を設け、超えた行は行全体を隠します |
| 権限 | 管理者権限は使いません(`asInvoker`) |
| ログ | 例外の情報のみを記録し、OCRで読み取った文字やNGワードは記録しません |
| 診断ログ | 既定はOFFです。ONにしても、記録するのは数値(CPU・メモリ・件数・処理時間)と操作の種類(「パニックON」など決まった文言)だけで、画面の文字・NGワード・ウィンドウのタイトル・プロセス名は記録しません |
| マウスフック | スクロールを即座に検知するため、低レベルマウスフック(`WH_MOUSE_LL`)を使います。処理するのはホイールの回転とその時のカーソル位置だけで、クリックやキー入力は見ず、何も記録しません。イベントはそのまま次に渡すので、スクロール自体は妨げません。「スクロール・表示の変化への対策」でOFFにするとフックを外します |

### 残るリスク(運用でカバーしてください)

- **操作パネルの非表示は保証されません。** `WDA_EXCLUDEFROMCAPTURE` は Microsoft のドキュメントで「セキュリティ機能ではない」とされています。また、プロジェクターに映っている画面にパネルを置くと会場から見えます。**パネルは手元のノートPCの画面に置いてください。**
- **アプリが終了・強制終了すると、すべてのマスクが消えます。** 本番前に起動していることを確認してください。
- **自動検出を OFF(`Ctrl+Alt+D`)にすると、自動検出の対象ウィンドウは隠されません。** これはユーザーの操作を優先するための仕様です。
- **OCR は読み取りを誤ることがあります。** 小さい文字・装飾された文字・画像内の文字は取りこぼすことがあります。確実に隠したいものは、ウィンドウ全体のマスクか手動マスクを使ってください。
- **DPAPI の鍵は Windows ユーザーに結び付いています。** 管理者がパスワードをリセットした場合などは復号できなくなり、NGワードの再登録が必要になります。

## 仕組みと制約

**画面共有は「画面全体」で行ってください。** マスクは別のウィンドウとして最前面に重ねているため、Teams/Zoom で特定のウィンドウだけを共有すると、マスクは共有されません。

| 項目 | 内容 |
|---|---|
| 自分の画面 | 手元の画面でもマスクされます(発表者にも見えなくなります) |
| 自動検出の遅れ | OCRの完了を待たずに、次の3段階で先に隠します。① ホイールを回した瞬間に、カーソルの下の対象ウィンドウ全体を塗りつぶす。② 0.1 秒ごとに対象ウィンドウを取り込み、ウィンドウの10%以上が前回から変わっていたとき、または3%以上の変化が2回続いたとき(スクロール・ページ切り替えなど。タッチパッドのゆっくりしたスクロールやスクロールバーでも)は、動きが止まって検査が終わるまで全体を塗りつぶす。スクロールで文字が動いた場所にあった古い検出マスクは、検査し直したときに消します(ずれたマスクが残らないように)。③ それより小さな変化は、変わった部分とその周囲1マス(48ピクセル四方単位)を、OCRが終わるまで塗りつぶす。OCRは変わった行だけを読み直します。それでも、取り込みの間隔(約0.1秒)より短い一瞬は見えることがあります。確実に隠したい画面は「ウィンドウ全体を隠す」か手動マスクを使ってください |
| 小さい文字 | v0.5.13〜0.5.16 から、変化した行だけを読むときなど小さい画像(100万ピクセル以下)は2倍に拡大してから OCR します(メモ帳の既定サイズの文字で、メールアドレスを読み落とす・途中までしか隠れない問題への対策)。また、OCR が「test@examp le.com」のようにドメインの途中で単語を分けた場合も、後ろの「le.com」まで隠します。OCR が1行を2つの行に分けて返した場合も、同じ高さですぐ右隣にある行はつなげて判定します。ドメインが「.com」などで終わっていない(読み取り途中の)アドレスは、すぐ右隣の単語を4つまで含めて隠します |
| 会議の映像・動画 | v0.5.12 から、3秒以上動き続け、その間スクロール(内容の上下のずれ)が見えないウィンドウ(Teams の会議画面の映像、動画など)は、ウィンドウ全体ではなく「変わった部分」(とその周囲1マス)だけを、OCR が終わるまで塗りつぶします。動き始めの3秒間は全体を隠します。映像が映り続けている部分は塗りつぶされたままになります。「自動検出」タブで OFF にすると、動いている間はずっと全体を隠します |
| 時計・会議タイマー | v0.5.11 から、直前のOCRで「時刻・日付のような短い数字」(例: `12:34`、`01:02:03`、`2026/11/19`、3桁以下の件数)しかなかったマスは、数字が変わっても先に塗りつぶしません(ちらつき防止)。OCR はこれまでどおり行い、数字以外の文字が出てきたら次からは通常どおり隠します。区切りのない4桁以上の数字(暗証番号・ワンタイムコード・電話番号など)は対象外です。変化が大きいとき(スクロールなど)は適用しません。「自動検出」タブでOFFにできます |
| 変化の判定 | 2×2 ピクセルごとの明るさの平均で比べます(v0.5.2 までは4ピクセルおきの点で比べていたため、細い文字の線を見逃し、隠しきれない「穴」ができていました)。幅4ピクセル以下の縦線だけの変化は、点滅するカーソルとみなして無視します。そのため、`l` や `|` のような細い1文字だけの変化は見逃すことがあります |
| 重なったウィンドウ | 背面のウィンドウを隠すマスクは、前面のウィンドウの上にも描かれます(隠しすぎる方向の動作) |
| ウィンドウの高速移動 | マスクは約30fpsで追従します。素早くドラッグすると端が一瞬見えることがあります |
| モザイク/ぼかし | 画像が用意できるまでは塗りつぶしで表示します。文字が判読できないよう、粗さ・強さは大きめを推奨します |
| ストアアプリ | プロセス名が `ApplicationFrameHost` になるため、タイトルで指定してください |
| 手動マスクのモザイク/ぼかし | マスクに重なるウィンドウを1つずつ取り込み(PrintWindow)、奥から順に重ね合わせて加工します。画面をそのまま取り込む方式(BitBlt)ではマスク自身が写り込むことを実機で確認したため、v0.3.0 でこの方式に変えました。一番下にはデスクトップ(壁紙・アイコン)を取り込みますが、取り込めない環境では灰色になります。タスクバーは取り込みません。更新間隔は「表示・ホットキー」タブで変更できます(既定 0.25 秒)。マスクに文字を表示する設定のときは、モザイクの上にも文字が出ます |
| 画面全体モード | 手前のウィンドウに完全に隠れたウィンドウは検査しません。メニュー・入力候補・ツールチップなどの小さなウィンドウも検査します(v0.5.6〜)。ONにした直後や新しいウィンドウが出た直後は、検査が終わるまでそのウィンドウ全体が隠れます(フェイルクローズ)。ウィンドウが多いと1周の検査時間が長くなります |
| メニュー・入力候補・ツールチップ | v0.5.6 から、ルールに一致したアプリ(本体)と同じプロセスのメニュー・入力候補・ツールチップも、本体と同じルールで扱います(「機密情報を隠す」なら検査、「常に隠す」なら隠す)。表示された直後は検査が終わるまで全体が塗りつぶされます。本体に付随するウィンドウかどうかは、「持ち主のウィンドウがある」「ツールウィンドウ」「タイトルバーとタイトルのないポップアップ」のいずれかで判定しています(経験則のため、アプリによっては判定から漏れることがあります) |
| Windows の通知・IME の変換候補 | 通知(トースト)や IME の変換候補は、対象アプリとは別のプロセスが表示するため、ルールでは対象になりません(画面全体モードでは検査します)。登壇中は Windows の「応答不可」(通知を止める設定)をONにしてください |
| 描画の順序 | 手動マスクのモザイク/ぼかしは、ほかの塗りつぶしマスクより下に描きます(塗りつぶしで隠した内容がモザイク越しに見えないようにするため) |

### キャプチャ方式(自動検出・モザイク用)

| 方式 | 根拠 | 特徴 |
|---|---|---|
| PrintWindow(既定) | `PrintWindow` は公式 API。ただし使用しているフラグ `PW_RENDERFULLCONTENT`(0x2)は**公式ドキュメントに記載がない**値 | 黄色い枠が出ない。アプリによっては黒い画像になる。取り込みのたびに対象アプリが描き直すため、映像を表示しているアプリ(Teams など)では時間がかかる。v0.5.10 から複数のウィンドウを同時に取り込む |
| Windows.Graphics.Capture | 公式 API | 安定しているが、パッケージ化していないアプリでは対象ウィンドウに**黄色い枠**が表示される(枠を消すにはパッケージマニフェストでの宣言が必要) |

## 初回の動作確認チェックリスト

本番の前に、次の順で確認してください。

1. [ ] ビルドが通り、起動する
2. [ ] 状態欄の「画面」の台数がモニターの台数と一致する
3. [ ] マスク編集でドラッグしたマスクが、ドラッグした位置にぴったり出る(拡大率 100% / 150% のモニターの両方で確認)
4. [ ] Teams の会議で「画面全体」を共有し、相手側(またはもう1台のPC)でマスクが見えること、操作パネルが見えないことを確認する
5. [ ] OBS の「画面キャプチャ」で録画し、マスクが映ることを確認する
6. [ ] Outlook などを「常に隠す」に設定し、ウィンドウを移動・最大化・最小化してマスクが追従する
7. [ ] ブラウザーを「機密情報を隠す(OCR)」に設定すると、最初の検査が終わるまで(1秒程度)ウィンドウ全体が隠れ、その後は該当箇所だけになる。続けて、「検出枠を赤線で表示」を ON にして、メールアドレスやGUIDの上に枠が正しく重なる
8. [ ] キャプチャ方式を Windows.Graphics.Capture に切り替えても、7 と同じ位置に枠が出る
9. [ ] NGワードに登録した日本語の氏名・顧客名が検出される(小さい文字でも試す)
10. [ ] `Ctrl+Alt+P` のパニックで全モニターが黒くなり、もう一度押すと戻る
11. [ ] `settings.json` をメモ帳で開き、NGワードが平文で書かれていない(`NgWordsProtected` が `dpapi1:` で始まる)
12. [ ] 日本語のOCR機能をいったん外した状態(または対象アプリが真っ黒に取り込まれる状態)で、自動検出の対象ウィンドウ全体が隠れ、状態欄に 🛡 の表示が出る
13. [ ] 手動マスクの見た目をモザイク/ぼかしにすると、下の画面が加工されて表示され、マスク自身が二重に写り込んでいない
14. [ ] 「表示・ホットキー」タブで画像を指定すると、塗りつぶしのマスクに画像が敷き詰めて表示される。マスクごとの「表示…」で文字・画像を個別に変えられる
15. [ ] 自動検出の対象のブラウザーで、マウスホイールで素早くスクロールすると、スクロール中はウィンドウ全体が塗りつぶされ、止めて少しすると該当箇所だけのマスクに戻る
16. [ ] タッチパッド・スクロールバーのドラッグ・PageDown キーでスクロールしたときも、スクロール中はウィンドウ全体が塗りつぶされ、マスクに穴(文字が見える隙間)がない。止まって少しすると該当箇所だけのマスクに戻る
17. [ ] 何も操作していないとき、画面下の「StageMask の使用量」の CPU が v0.4.0 より下がっている

### 画面下の「StageMask の使用量」について

| 表示 | 意味 |
|---|---|
| CPU | StageMask 自身が使った CPU 時間 ÷(経過時間 × 論理プロセッサ数)。全コアを使い切った状態を 100% とし、直近数秒をならして1秒ごとに更新します |
| メモリ 物理 | 作業セット(`Process.WorkingSet64`)。物理メモリ上にあるページで、ほかのアプリと共有している分を含みます |
| メモリ 専用 | `Process.PrivateMemorySize64`。ほかのアプリと共有しない確保量(Private Bytes 相当) |

タスクマネージャーの値とは数え方が異なるため、一致しないことがあります。

### 診断ログ(開発・動作確認用)

「表示・ホットキー」タブの「診断ログ」をチェックすると、すぐに記録を始めます(既定はOFF)。

- 保存先: `%APPDATA%\StageMask\diag\diag-日時.csv`(UTF-8 BOM付き。Excel でそのまま開けます)
- 1秒に1行。1ファイル10MB(約5万行、14時間程度)を超えたら次のファイルに切り替え、新しい10ファイルだけを残します
- 「ログのフォルダーを開く」でエクスプローラーが開きます

| 列 | 内容 |
|---|---|
| time | 記録した時刻(PCのローカル時刻) |
| cpu_percent / working_set_mb / private_mb / threads | 画面下に表示しているものと同じ値 |
| gc_heap_mb | .NET が管理しているメモリの量(増え続ける場合はメモリリークの疑い) |
| overlays / hidden_windows / detect_targets | 画面の台数、全体を隠しているウィンドウ数、OCR対象のウィンドウ数 |
| detection_masks / pending_masks / scroll_masks / fail_closed | 検出マスク、未検査で隠している箇所、スクロール中で隠しているウィンドウ、検査できずに全体を隠しているウィンドウの数 |
| ocr_cycle_ms / check_round_ms | OCR1周と変化確認1回の時間 |
| ocr_full / ocr_bands / ocr_skipped | その1秒間に、OCRを全体で行った回数・変わった行だけ行った回数・変化がなく飛ばした回数 |
| capture_failures / wheel_events | その1秒間の取り込み失敗とホイール操作の回数 |

| check_capture_ms / check_signature_ms | その1秒間に、変化の確認(0.1秒ごと)でウィンドウの取り込みにかかった時間と、変化の判定(指紋の計算)にかかった時間の合計 |
| max_capture_ms | その1秒間で、ウィンドウ1つの取り込みにかかった最長時間。大きい場合、取り込みに時間がかかるウィンドウがある |

## リリースの作り方(開発者向け)

1. `src/StageMask.App/StageMask.App.csproj` の `<Version>` を新しい番号にしてコミット・push する
2. 次のどちらかでリリースを作る
   - **かんたん**: GitHub の「Actions」タブ → 左の「release」→「Run workflow」→「Run workflow」。ブラウザーやスマホのアプリからでも実行できる。`<Version>` の番号でタグ(例: `v0.5.9`)を自動で作る
   - **コマンド**: 同じ番号のタグを付けて push する(`git tag v0.5.9` → `git push origin v0.5.9`)。タグと `<Version>` が違うと途中で止まる
3. 数分で、テスト → exe の作成 → [リリースページ](../../releases) の作成までが自動で終わる。同じ番号のリリースが既にある場合は止まる(上書きしない)
